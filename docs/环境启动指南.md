# 环境启动指南

> 基于 Node.js 的多环境启动系统，通过独立配置文件管理开发、测试、生产三套环境。

---

## 1. 快速开始

```bash
# 开发环境（前后端 + 热重载）
npm run start:dev

# 测试环境（编译产物，端口 3002）
npm run start:test

# 生产环境冒烟测试（编译产物，端口 3003）
npm run start:prod
```

---

## 2. 启动命令详解

### 2.1 命令格式

```bash
node scripts/start.js --env <environment> [选项]
```

### 2.2 选项说明

| 选项 | 简写 | 说明 |
|------|------|------|
| `--env <env>` | `-e` | 指定环境：`development` / `test` / `production`（**必填**） |
| `--backend-only` | `-b` | 仅启动后端服务 |
| `--frontend-only` | `-f` | 仅启动前端开发服务器（仅 `development` 模式） |
| `--help` | `-h` | 显示帮助信息 |

### 2.3 使用示例

```bash
# 启动开发环境（前后端同时启动）
npm run start:dev
# 等价于: node scripts/start.js --env development

# 仅启动后端（开发模式，tsx watch 热重载）
npm run start:dev -- -b

# 仅启动前端开发服务器
npm run start:dev -- -f

# 启动测试环境
npm run start:test

# 启动生产环境冒烟测试
npm run start:prod
```

> **注意**：通过 npm run 传递额外参数时需加 `--` 前缀，例如 `npm run start:dev -- -b`。

### 2.4 停止服务

- **Ctrl+C**：在启动终端按 Ctrl+C，脚本会优雅关闭所有子进程
- **停止脚本**：`bash scripts/stop.sh -e <dev|test|prod>`

## 3. 环境配置文件

### 3.1 目录结构

```
environments/
├── development.config.js    # 开发环境配置
├── test.config.js           # 测试环境配置
└── production.config.js     # 生产环境配置
```

### 3.2 配置参数说明

每个配置文件导出一个对象，包含以下字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `name` | string | 环境名称 |
| `nodeEnv` | string | NODE_ENV 值 |
| `mode` | string | 运行模式：`development`（tsx watch）/ `production`（编译产物） |
| `backend.port` | number | 后端端口 |
| `backend.host` | string | 后端监听地址（留空绑定所有接口） |
| `frontend.port` | number | 前端端口（仅 dev 模式启动） |
| `frontend.host` | string | 前端监听地址 |
| `database.host` | string | MySQL 主机地址 |
| `database.port` | number | MySQL 端口 |
| `database.user` | string | MySQL 用户名 |
| `database.password` | string | MySQL 密码 |
| `database.name` | string | MySQL 数据库名称 |
| `api.basePath` | string | API 基础路径 |
| `logging.level` | string | 日志级别：`debug` / `info` / `warn` / `error` |
| `paths.dataDir` | string | 数据目录（相对项目根目录） |
| `paths.logDir` | string | 日志目录 |
| `paths.exportDir` | string | 导出目录 |
| `paths.pidFile` | string | PID 文件路径 |
| `healthCheckTimeout` | number | 健康检查超时秒数 |

### 3.3 环境对比

| 参数 | 开发环境 | 测试环境 | 生产环境 |
|------|----------|----------|----------|
| 后端端口 | 3001 | 3002 | 3003 |
| 前端端口 | 5173 | 5174 | 80（不启动） |
| 数据库 | quote_system | quote_system_test | quote_system_prod |
| 运行模式 | tsx watch 热重载 | 编译产物 | 编译产物 |
| 前端 dev server | ✅ 启动 | ❌ 不启动 | ❌ 不启动 |
| 日志级别 | debug | info | warn |
| 健康检查超时 | 15s | 15s | 30s |

## 4. 启动脚本工作流程

```
1. 解析参数 (--env)
   └─ 未指定/不存在 → 报错退出

2. 加载配置文件 (environments/<env>.config.js)
   └─ 动态 import 配置模块

3. 注入环境变量到 process.env
   └─ PORT / MYSQL_* / NODE_ENV / EXPORT_STORAGE_PATH
   └─ 子进程继承这些变量，覆盖 api/.env 默认值

4. 预检查
   ├─ 端口是否被占用
   ├─ PID 文件是否残留
   └─ 生产模式：检查 api/dist/index.js 是否存在

5. 启动后端
   ├─ dev 模式: npx tsx watch api/index.ts
   └─ prod 模式: node api/dist/index.js
   └─ 等待端口就绪 + 健康检查 (/api/health)

6. 启动前端（仅 dev 模式）
   └─ npx vite --port <port> --host

7. 信号处理
   ├─ SIGINT/SIGTERM → 优雅关闭所有子进程
   └─ 清理 PID 文件
```

## 5. 与现有 bash 脚本的关系

项目同时支持两套启动方式：

| 方式 | 命令 | 适用场景 |
|------|------|----------|
| Node.js 启动器 | `npm run start:dev` | 日常开发，配置文件管理清晰 |
| Bash 启动脚本 | `bash scripts/start.sh -e dev` | 运维场景，支持守护进程模式 |

两者共用相同的端口、数据库配置，可互换使用。Node.js 启动器侧重开发便捷性，Bash 脚本侧重运维功能（守护进程、蓝绿部署、回滚等）。

## 6. 环境切换注意事项

1. **端口隔离**：三个环境使用不同端口（3001/3002/3003），可同时运行
2. **数据库隔离**：每个环境使用独立数据库，数据互不影响
3. **编译产物**：test/production 环境需要先执行 `npm run build` 生成 `api/dist/`
4. **配置优先级**：start.js 注入的环境变量 > `api/.env` 文件 > 代码默认值
5. **前端开发服务器**：仅 development 模式启动 Vite dev server；test/production 模式由后端托管 `dist/` 静态文件
6. **数据库迁移**：后端启动时自动检测并执行待应用的迁移（通过 `schema_migrations` 表追踪版本）

## 7. 自定义配置

如需修改某个环境的配置，直接编辑对应的配置文件：

```bash
# 例如修改开发环境端口
vi environments/development.config.js
# 将 backend.port 从 3001 改为 3005
```

修改后无需重启或重新构建，下次执行 `npm run start:dev` 即生效。

### 添加新环境

1. 在 `environments/` 目录创建新配置文件（如 `staging.config.js`）
2. 在 `scripts/start.js` 的 `VALID_ENVS` 数组中添加环境名称
3. 在 `package.json` 添加对应的 npm script
