# 产品成本项配置 - 列表与详情页设计文档

> 状态：**已实现（2026-09-11）**
> 涉及范围：列表查询页（ProductCostItemList.tsx，`/product-cost-items`）、编辑详情页（ProductCostItems.tsx，`/product-cost-items/:id`）、路由（App.tsx）、单元测试（tests/productCostItemList.test.tsx、tests/productCostItemsDetail.test.tsx）

---

## 1. 需求概述

| # | 需求 | 实现方案 |
|---|------|---------|
| 1 | 列表查询页采用树形结构展示「成本项（父级）→ 可选工艺（子级）」，默认完全展开 | 扁平化行序列 `buildTreeRows`，折叠集合默认为空集 |
| 2 | 父/子字段差异大，需两套独立表头；子级表头随各子列表内嵌展示（不统一置顶），并承载该成本项的自定义字段名 | 父级表头（深蓝底 bg-blue-600）置顶 sticky；子级表头（浅蓝底 bg-blue-100）内嵌在每个子列表之前，字段列为：工艺名称/成本金额/计算公式/特点描述/备注 + 该成本项的**自定义字段名**（逐组独立） |
| 3 | 视觉层级清晰（缩进/连接线/图标），表头与其子列表数据（含自定义字段值）逐组对应 | 子表头紧随父行、先于该子列表工艺行；子行缩进 + CornerDownRight 连接线 + Wrench 图标；工艺行按列展示自定义字段值（与子表头字段名逐列对应） |
| 4 | 成本项名称 + 工艺名称模糊查询，输入即过滤、实时响应 | `useMemo` 派生过滤结果（无防抖延迟），大小写不敏感 substring，命中黄色高亮 |
| 5 | 大数据量性能 | 固定行高虚拟滚动（可视窗口 ± 缓冲行渲染） |
| 6 | 现有页面改造为编辑详情页，设计语言与列表页一致 | 路由 `/product-cost-items/:id`，URL 参数定位成本项，页头返回列表 + 成本项切换器 |
| 7 | 所有交互有明确状态反馈 | 加载 Spinner / 错误横幅 / 提交中禁用 / 空态与无结果引导 |

## 2. 路由设计

| 路由 | 页面 | 权限 | 说明 |
|------|------|------|------|
| `/product-cost-items` | ProductCostItemList（列表查询页） | `process-costs:view` | 树形总览 + 查询 + 新增入口 + 删除 |
| `/product-cost-items/:id` | ProductCostItems（编辑详情页） | `process-costs:view` | 单成本项的完整编辑（工艺 CRUD + 自定义字段 CRUD） |
| `/process-costs` | 重定向 → `/product-cost-items` | — | 旧路径兼容 |

列表页 → 详情页的四个入口：
1. 父/子行内「详情」按钮（ChevronRight 图标）
2. 双击父行或子行
3. 新增成本项成功后自动跳转（继续配置工艺与字段）
4. 侧边栏菜单（基础设置 → 产品成本项配置）

### 3.2 表头设计（父级置顶 + 子级随子列表内嵌）

**父级表头**（`thead`，sticky 置顶，深蓝 bg-blue-600 白字，「父」徽标）：

| 表头字段 | 对应数据 | 说明 |
|---------|---------|------|
| 成本项名称 / 工艺数量 / 字段数量 / 更新时间 / 创建时间 / 操作 | `product_cost_items` | 字段数量列显示总字段数，存在隐藏字段时补注「（N 显示）」 |
| 自定义字段（跨列占位） | — | 当全表存在自定义字段列时，父级表头以跨列单元格标注该区域，悬停提示「字段名见各子列表的子级表头」 |

**子级表头**（`tbody` 内 subheader 行，浅蓝 bg-blue-100 蓝字，「子」徽标，内嵌于每个子列表之前）：

| 表头字段 | 对应数据 | 说明 |
|---------|---------|------|
| 工艺名称 / 成本金额（元）/ 计算公式 / 特点描述 / 备注 / 操作 | `product_cost_processes` | 基础字段，与父级表头字段语义独立 |
| 自定义字段名 ×N | `product_cost_custom_fields`（该成本项 visible=true 的字段） | **逐组独立**：每个子列表展示且仅展示其所属成本项配置的自定义字段名，带 Tag 图标，悬停提示字段类型（文本/数字/日期/下拉选择） |

**自定义字段列对齐规则**：表格总列数 = 6 + 全表最大自定义字段数（`maxCustomFields`，按过滤结果的可见字段取最大值）。自定义字段数不足的子列表/父行以跨列空单元格（`colSpan`）对齐，保证各子列表自定义字段列起始位置一致。

### 3.3 树形视觉层级

- **父行**：折叠箭头（ChevronDown/ChevronRight，aria-label「展开/折叠 {名称}」）+ Folder/FolderOpen 图标（折叠态合拢、展开态打开）+ 粗体名称，整行淡蓝底
- **子表头行**：紧随父行（父行的下一行）、先于该子列表工艺行——「表头跟随子列表」；浅蓝底 + 「子」徽标，随子列表一同折叠/展开、一同被查询过滤
- **子行（工艺行）**：固定左缩进（pl-9）+ CornerDownRight 连接线 + Wrench 工艺图标，常规底色；自定义字段值按列展示（与子表头字段名逐列对应），单元格 `title` 回显「字段名：值」，未配置值显示「—」

### 3.4 展开/折叠控制

| 操作 | 行为 |
|------|------|
| 点击父行折叠箭头 | 切换该成本项折叠状态（折叠集合 `collapsedIds` 增删该 id） |
| 「全部展开」 | 清空折叠集合 |
| 「全部收起」 | 折叠集合置为当前过滤结果全部成本项 id |
| 默认状态 | 折叠集合为空 = **完全展开** |
| 查询激活期间 | `forceExpand=true` 强制展开所有结果节点（保证命中工艺可见）；折叠状态保留，清空查询后恢复 |

### 3.5 模糊查询设计

**双输入框**：成本项名称 / 工艺名称，均带 Search 图标与独立清空按钮（X）。

**匹配规则**（`filterCostTree`，多条件 AND 组合）：
- 大小写不敏感 substring（`name.toLowerCase().includes(query)`）
- `itemQuery` 命中 → 成本项可见；此时若另有 `processQuery`，仅展示命中工艺
- `processQuery` 命中 → 命中工艺可见，且其父项强制可见（父项名称未命中也可达）
- 父项不可见 ⇔（名称未命中）∨（有工艺查询且无任何工艺命中）

**实时响应**：`useMemo([items, itemQuery, processQuery])` 派生过滤结果，每次按键立即重算，无防抖延迟；输入过程中动态匹配。

**结果反馈**：
- 命中文本黄色高亮（`<mark>` 黄底，正则特殊字符已转义，全部出现处高亮）
- 右侧计数：「命中 X 个成本项 / Y 条工艺（共 M / N）」
- 无结果时展示查询词回显 + 「清空查询条件」按钮
- 清空单个查询：输入框右侧 X 按钮；一键清空：无结果态按钮

### 3.6 虚拟滚动（性能设计）

| 参数 | 值 | 说明 |
|------|----|------|
| `ROW_HEIGHT` | 52px | 父/子行统一行高（表格行高受内容影响统一为 36px 内容区 + padding） |
| `OVERSCAN` | 6 | 可视窗口上下缓冲行数 |
| `FALLBACK_VIEWPORT` | 640px | ResizeObserver 未生效（测试环境）的视口兜底 |

**机制**（`computeVisibleRange`）：
1. 滚动容器 `max-h-[calc(100vh-320px)]`，`onScroll` 记录 `scrollTop`
2. `ResizeObserver` 跟踪容器实际视口高度（≥240px）
3. 计算 `[start, end)` 渲染区间 = 可视行 ± overscan
4. 表头 `sticky top-0` 滚动吸顶
5. 顶部/底部占位行（`aria-hidden`，高度 = 区外行数 × 行高）撑出完整滚动高度

效果：任意行数下 DOM 节点数恒定 ≈ 视口行数 + 2×缓冲，万行级数据滚动无卡顿。行数 ≥100 时底部提示「已启用虚拟滚动」。

### 3.7 列表页操作

| 操作 | 权限 | 反馈 |
|------|------|------|
| 新增成本项 | `process-costs:create` | 内联表单（名称必填）→「创建并配置」→ 跳转详情页 |
| 删除成本项/工艺 | `process-costs:delete` | 共用 DeleteConfirmDialog（含引用检查），成功后静默刷新列表 |
| 进入详情 | `process-costs:view` | 详情按钮 / 双击行 |

### 4.2 改造要点（相对旧版单页）

| 改动 | 说明 |
|------|------|
| URL 参数定位 | `useParams` 取 `:id`，加载后选中对应成本项；直接展示该项工艺/字段，不再渲染左侧全量列表 |
| 成本项切换器 | 页头 select（aria-label「当前成本项」），切换时 `navigate(replace)` 同步 URL；仅一个成本项时禁用 |
| 返回列表 | 页头「← 返回列表」按钮；id 无效时错误卡片内亦有该按钮 |
| 无效链接 | id 不存在 → 「成本项不存在或已被删除」提示卡片，不渲染详情区 |
| 工艺手动排序 | 操作列「上移工艺/下移工艺」按钮（首行上移、末行下移禁用；仅一条工艺不渲染；需 `process-costs:edit` 权限），相邻交换后调用 `PUT /product-cost-items/:id/processes/reorder` 整表原子重排（事务内重写 sort_order 为 1..N，传入列表须与该成本项现有工艺集合完全一致，否则 400）；列表页展示顺序同步跟随 |
| 动态字段联动 | 工艺表单按 `visible=true` 的自定义字段自动渲染输入控件（text/number/date/select 四型），select 按字段 options 渲染下拉；工艺表格同步展示动态列 |
| 保留功能 | 工艺 CRUD、自定义字段 CRUD（含上移/下移排序）、编辑成本项名称、删除（含引用检查）等完整编辑能力不变 |

## 5. 状态反馈设计

| 场景 | 反馈 |
|------|------|
| 列表加载中 | 表格区 Loader2 旋转图标 + 「加载中...」 |
| 加载失败 | 页面顶部红色横幅（可关闭） |
| 空数据 | 「暂无成本项配置，点击右上角『新增成本项』开始配置」（有创建权限时） |
| 查询无结果 | 查询词回显 + 清空按钮 |
| 表单提交中 | 按钮 Spinner + disabled |
| 提交成功 | 新增成本项直接跳转详情页继续配置；其余沿用页面内既有成功/失败提示 |
| 删除 | 二次确认对话框（含引用检查），成功后刷新 |

## 9. 设计决策记录

1. **虚拟滚动而非分页**：树形结构分页会切断父子关系；行高固定 + 可视窗口渲染兼顾完整树与性能，万行级无卡顿。
2. **查询强制展开**：命中工艺若被折叠则不可见，违背查询语义；折叠状态保留、清空查询后恢复，兼顾用户习惯。
3. **子级表头随子列表内嵌（不统一置顶）**：各成本项的自定义字段配置不同，全局子级表头无法承载逐组差异；将子级表头内嵌到每个子列表之前，字段名与该子列表数据（含自定义字段值）逐组对应，滚动时表头始终与其子列表同屏可见，数据关联更直观。父级表头保持置顶 sticky（父行分布于全表，需要常驻标注）。
4. **自定义字段列按「全表最大列数 + 跨列对齐」**：各子列表自定义字段数不同，以 `maxCustomFields`（过滤结果可见字段最大值）确定表格总列数，不足的子列表/父行以 `colSpan` 空单元格对齐，保证各子列表自定义字段列起始位置一致、同组表头与数据列严格对齐。
5. **列表页不展开动态字段列（已废弃，改为逐组展示）**：早期方案中列表页不展示自定义字段值，仅靠工艺名称 `title` 悬停速览；现按需求改为子表头内嵌自定义字段名 + 工艺行按列展示字段值，与详情页工艺表格的动态列设计语言一致。
6. **新增后跳转详情页**：新成本项无工艺无字段，列表页仅能建名称；跳转详情页引导完成完整配置。
7. **详情页 URL 化**：`/product-cost-items/:id` 支持收藏/分享/前进后退；切换器 `navigate(replace)` 避免污染历史栈。
8. **工艺排序用批量重排端点而非逐行改序**：相邻交换若只改两行的 sort_order 会产生重复序号（次序不稳定）；`PUT /:id/processes/reorder` 一次性提交整表新顺序，事务内重写为 1..N，原子且幂等，并做集合一致性校验（漏传/混入他项工艺直接 400），天然处理并发增删。自定义字段排序因已有单行 `sortOrder` 更新通道，维持逐行写入不变。
