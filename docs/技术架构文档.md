## 3. 前端架构

### 3.1 路由设计

```
/login                           → Login（公开）
/register                        → Register（公开）
/                                → Dashboard（需认证）
/quotes                          → Quotes（订单列表）
/quotes/new                      → BagQuote（新建报价）
/quotes/:id                      → BagQuote（查看报价）
/quotes/:id/edit                 → BagQuote（编辑报价）
/quotes-table/new                → BagQuoteTable（表格版新建）
/quotes-table/:id                → BagQuoteTable（表格版查看）
/quotes-table/:id/edit           → BagQuoteTable（表格版编辑）
/quotes-wps                      → BagQuoteWps（WPS版）
/process-costs                   → ProcessCost
/customers                       → Customers
/customers/new                   → CreateCustomer
/customers/:id                   → CustomerDetail
/customers/:id/edit              → CreateCustomer
/products                        → Products
/products/new                    → CreateProduct
/products/:id                    → ProductDetail
/tasks                           → Tasks
/tasks/:id                       → TaskDetail
/reports                         → Reports
```

**认证守卫**：`App.tsx` 中通过 `useAuthStore` 的 `isAuthenticated` 判断，未认证时重定向到 `/login`。

### 3.2 状态管理

使用 Zustand 管理全局认证状态（`src/store/auth.ts`）：
- `isAuthenticated`：登录状态
- `user`：当前用户信息
- `initAuth()`：初始化时从 Cookie 恢复登录状态
- `login()` / `logout()`：登录/登出

页面级状态使用 React `useState` + `useRef`，无全局业务状态管理。

### 3.3 API 层

`src/api/index.ts` 封装所有前端 API 调用，按领域分组：

```typescript
api.orders    // getAll, getById, update, delete
api.customers // getAll, getById, getByName, create, update, delete
api.products  // getAll, getById, create, update, delete
api.tasks     // getAll, getById, create, update, delete
api.quotes    // getAll, getById, create, update, delete, nextStatus, prevStatus, endQuote
api.processCosts // getAll, getById, create, update, delete
```

所有调用使用 `fetch`，基础路径 `/api`（Vite 代理到后端 3001 端口）。

### 3.4 在线表格架构（VTable-Sheet）

**核心组件**：`BagQuote.tsx` / `BagQuoteTable.tsx`

**初始化流程**：
1. 根据款式选择对应模板（`getTemplateByStyle`）
2. 将模板 `data` + `formulas` 载入 VTableSheet 实例
3. 注册 `change_cell_value` 事件监听器
4. 启动 `ResizeObserver` 监听容器尺寸变化

**公式引擎**：
- 使用 VTable-Sheet 内置 `formulaManager`
- 公式以单元格地址（如 `B3`、`J9`）为 key 存储
- 编辑单元格后触发级联重算（`handleCellValueChanged` + 兜底 `recascadeDependents`）

**数据同步**：
- 表格 → 订单信息：`syncFromTable()` 从公式引擎读取卖价、规格、数量
- 订单信息 → 表格：成品行宽高修改时同步到正反面行

**模板系统**：
- 6 个 `SheetTemplate` 常量，每个含 `data`（二维数组）和 `formulas`（单元格公式映射）
- 切换款式时通过 `useEffect([orderInfo.productStyle])` 自动重载模板

## 4. 后端架构

### 4.1 API 路由

| 路由前缀 | 文件 | 功能 |
|---|---|---|
| `/api/quotes` | routes/quotes.ts | 报价/订单 CRUD + 状态流转 |
| `/api/customers` | routes/customers.ts | 客户 CRUD |
| `/api/products` | routes/products.ts | 产品 CRUD |
| `/api/orders` | routes/orders.ts | 订单 CRUD |
| `/api/tasks` | routes/tasks.ts | 任务 CRUD |
| `/api/process-costs` | routes/processCosts.ts | 工艺成本 CRUD |
| `/api/bag-quote` | routes/bagQuote.ts | 报价试算计算 |
| `/api/upload` | routes/upload.ts | 文件上传 / Excel 导入 |
| `/api/export` | routes/export.ts | 订单 Excel 导出 |
| `/api/health` | index.ts | 健康检查 |

### 4.2 数据访问层（db.ts）

`db.ts` 是数据访问的统一出口，使用 sql.js（WASM 版 SQLite）实现本地文件持久化（`./data/quote-system.db`）。通过 `MigrationRunner` 管理 schema 版本迁移。所有方法为同步调用（sql.js 特性），路由层用 `asyncHandler` 包装以统一错误处理。详见 [数据库文档](./数据库文档.md)。

**Quote 状态流转核心逻辑**：

```
nextStatus(id):  1→2→3→4→5→6，进入节点时记录对应时间
prevStatus(id):  2→1, 3→2, 4→3, 5→4, 6→5，退回上一节点
endQuote(id):    1或2 → 6，直接结束
```

**订单号生成逻辑**：
```
quote_number = `${customerName}-${timestamp(14位)}-${styleLabel}`
```
更新时保留原时间戳，仅替换客户名称和款式。

### 4.3 报价计算服务（bagQuoteCalculator.ts）

独立计算服务，接收 `BagQuoteInput`（数量、宽、高、底、正反面行等），输出成本和卖价。被 `bagQuote` 路由调用。

### 4.4 中间件

| 中间件 | 说明 |
|---|---|
| `helmet()` | 安全头配置（V0.2 新增） |
| `cors()` | 跨域支持 |
| `express.json({ limit: '50mb' })` | JSON 解析（支持大 body，图片 base64） |
| 无认证中间件 | V0.2 仅前端路由守卫，API 层未校验 token |

## 5. 数据流

### 5.1 报价创建流程

```
用户填写表单 → 点击保存
  → 前端组装 Quote 数据（含表格快照）
  → POST /api/quotes
  → db.quotes.create() 生成订单号 + 初始化状态(1) + 记录 quoteTime
  → 返回新 Quote
  → 前端跳转到编辑页
```

### 5.2 表格公式计算流程

```
用户编辑单元格 → VTable change_cell_value 事件
  → formulaManager 级联重算依赖单元格
  → recascadeDependents 兜底（拓扑排序 + 逐个更新）
  → syncFromTable() 读取卖价/规格/数量 → 更新 React state
  → 表单字段显示更新
```

### 5.3 状态流转流程

```
用户点击"下一节点"
  → POST /api/quotes/:id/next-status
  → db.quotes.nextStatus() 切换状态 + 记录时间节点
  → 返回更新后的 Quote
  → 前端刷新状态显示 + 进度条
```

## 6. 关键技术决策

| 决策 | 原因 |
|---|---|
| VTable-Sheet 而非自研表格 | 内置公式引擎，支持 Excel 级联计算，减少开发量 |
| sql.js (SQLite WASM) | 零原生编译依赖，文件持久化，开发/生产一致 |
| Zustand 而非 Redux | 轻量，仅认证状态需全局管理，页面状态用 useState |
| Tailwind CSS 而非 CSS Modules | 快速迭代，原子化样式便于布局调整 |
| 款式模板硬编码为常量 | 模板结构固定且复杂，硬编码比动态配置更可靠 |
| recascadeDependents 兜底 | VTable 1.26.5 的 handleCellValueChanged 公式级联不可靠 |

## 7. 部署架构

### 7.1 开发环境

```
npm run dev
  → concurrently 同时启动:
    → vite (前端 5173)
    → tsx watch api/index.ts (后端 3001)
  → Vite 代理 /api → localhost:3001
```

### 7.2 生产构建

```
npm run build
  → vite build → dist/
  → 静态文件部署到 CDN/Nginx
  → 后端: npm run build:backend → api/dist/
  → node api/dist/index.js
```

### 7.3 环境配置

`api/.env`：
```
DB_PATH=./data/quote-system.db  # 数据库文件路径（默认 ./data/quote-system.db，:memory: 为内存模式）
PORT=3001                        # 后端端口
EXPORT_STORAGE_PATH=             # Excel 导出存储路径
```
