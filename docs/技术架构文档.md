### 3.3 状态管理

使用 Zustand 管理全局认证状态（`src/store/auth.ts`）：

- `isAuthenticated` / `user` / `accessToken`（存内存）/ `permissions`（权限码列表）
- `login(email, password)`：调用 `/api/auth/login`，保存 access token（内存）+ refresh token（localStorage 轻混淆加密存储）
- `initAuth()`：页面刷新时用 refresh token 调用 `/api/auth/refresh` + `/api/auth/me` 恢复登录态与权限列表
- `refreshToken()`：单例 Promise 防并发刷新；401 时由 API 层自动触发并重试请求
- `recordActivity()` / `checkTokenStatus()`：临近过期（剩余 ≤ 5 分钟且用户活跃）自动续期；`IdleMonitor` 组件实现 10 分钟无操作自动登出 + 过期前 30 秒警告弹窗
- `hasPermission(code)` / `hasAnyPermission(...codes)`：按钮级权限控制

页面级状态使用 React `useState` + `useRef`，无全局业务状态管理。

### 3.4 API 层

`src/api/index.ts` 封装所有前端 API 调用，按领域分组（orders / customers / products / tasks / quotes / processCosts / sheetTemplates / users / roles / permissions / operationLogs / reconciliation 等）。

- 统一 `authFetch()`：自动附加 `Authorization: Bearer <token>` 和 `X-Operator`（审计操作人，中文 URL 编码）请求头
- 401 自动刷新：收到 401 时调用 `refreshToken()` 换新 token 后重试一次
- 基础路径 `/api`（Vite 开发代理到后端）

### 3.5 在线表格架构（VTable-Sheet）

**核心组件**：`BagQuote.tsx` / `BagQuoteTable.tsx`

**初始化流程**：
1. 根据订单 `productStyle` + `template_id` 加载款式模板（优先数据库 `sheet_templates`，内置模板常量兜底）
2. 将模板 `data` + `formulas` 载入 VTableSheet 实例（叠加订单持久化的 `tableData` / `modifiedFormulas` / `allFormulas` / `removedFormulaAddresses`）
3. 注册 `change_cell_value` 事件监听器
4. 启动 `ResizeObserver` 监听容器尺寸变化

**公式引擎**：使用 VTable-Sheet 内置 `formulaManager`，公式以单元格地址为 key 存储；编辑后级联重算 + `recascadeDependents` 兜底（拓扑排序）。

**模板系统（v19 起）**：款式模板存数据库 `sheet_templates` 表，同一款式可建多个差异化模板（一对多，v23），前端 `SheetTemplates` 页面在线可视化编辑；前端内置 6 个 `SheetTemplate` 常量作为兜底。

### 4.2 数据访问层（db.ts / dbClient.ts）

```
api/dbClient.ts
  ├── pool                    # mysql2 连接池单例
  ├── initDatabase()          # 确保 MySQL 数据库存在
  ├── withTransaction(fn)     # 事务封装（独占连接）
  ├── execMultiStatement(sql) # 多语句拆分执行（用于迁移 DDL）
  └── closePool()             # 关闭连接池

api/db.ts（dbApi）
  ├── MigrationRunner         # 迁移管理（详见数据库文档）
  ├── quotes                  # CRUD + 状态流转 + 复制 + 对账(reconciliation)
  ├── productionTasks         # 做货流程任务（甘特图数据）
  ├── reconciliation          # 对账成本明细 + reconcileQuote / unreconcileQuote
  ├── customers / products / orders / tasks / processCosts
  ├── sheetTemplates          # 款式模板（一对多）
  ├── users / roles / permissions（RBAC）
  └── operationLogs           # 操作日志
```

**Quote 状态流转核心逻辑**（v14 指针模式 + v28 对账）：

```
nextStatus(id):   1→2→7→3→4→5，进入节点时记录对应时间
                  5 不再前进（5→8 只能经订单对账管理 reconcileQuote 确认）
                  8（已对账）为流转终态；6（结束）为旁路终态
prevStatus(id):   2→1, 7→2, 3→7, 4→3, 5→4, 6→5（历史"结束"可退回重新走对账）
                  8 不可手动回退（8→5 仅可经 unreconcileQuote 退回对账）
endQuote(id):     1/2/7 → 6，直接结束
reconcileQuote(id):     5→8，记录 reconciledTime（对账时间）
unreconcileQuote(id):   8→5，清空 reconciledTime（重新核对后可再次确认）
```

状态枚举：`1 报价中 → 2 打样中 → 7 打样完成 → 3 做货中 → 4 已发货未收款 → 5 已发货已收款 → 8 已对账（终态）`；`6 结束`（旁路）。待收总额（pendingAmount）仅在做货中(3)/已发货未收款(4)状态计算保留。

**订单号生成逻辑**：
```
quote_number = 16 位随机数字（全局唯一）
生成后查询防碰撞（重试 10 次），兜底：时间戳(13位) + 3位随机数
创建后不再随客户名称/款式变化
```

### 4.3 认证与权限（services/auth.ts + middleware/auth.ts）

- JWT 双 Token：access token 15 分钟（`JWT_ACCESS_EXPIRES_IN=15m`）、refresh token 7 天（`JWT_REFRESH_EXPIRES_IN=7d`），分别用 `JWT_SECRET` / `JWT_REFRESH_SECRET` 签名
- 密码哈希 bcryptjs（10 轮）
- `authenticate` 中间件校验 `Authorization: Bearer` 头；`requirePermission(code)` 校验 RBAC 权限（users/roles/permissions/role_permissions/user_roles 五表模型）
- RBAC 权限目录 43 项（menu/button 两类），admin 角色拥有全部权限

### 4.4 报价计算服务（bagQuoteCalculator.ts）

独立计算服务，接收 `BagQuoteInput`（数量、宽、高、底、正反面行等），输出成本和卖价。被 `bagQuote` 路由调用，测试直接覆盖。

### 4.5 中间件

| 中间件 | 说明 |
|---|---|
| `helmet({ contentSecurityPolicy: false, hsts: false })` | 安全头（局域网部署禁用 CSP/HSTS） |
| `compression({ level: 6, threshold: 1024 })` | gzip 压缩响应体 |
| `cors()` | 跨域支持 |
| `express.json({ limit: '50mb' })` | JSON 解析（支持大 body，图片 base64） |
| `authenticate` | JWT 认证（全部业务路由） |
| `requirePermission(code)` | RBAC 权限校验（敏感操作） |

生产环境（`NODE_ENV=production`）Express 直接托管前端 `dist/` 静态文件并回退 SPA 路由；支持优雅关闭（SIGTERM/SIGINT，10 秒兜底强制退出）。

## 5. 数据流

### 5.1 报价创建流程

```
用户填写表单 → 点击保存
  → 前端组装 Quote 数据（含表格快照 tableData/formulas）
  → POST /api/quotes（Bearer token + X-Operator 审计头）
  → db.quotes.create() 生成 16 位随机订单号 + 初始化状态(1) + 记录 quoteTime
  → 返回新 Quote → 前端跳转到编辑页
```

### 5.2 表格公式计算流程

```
用户编辑单元格 → VTable change_cell_value 事件
  → formulaManager 级联重算依赖单元格
  → recascadeDependents 兜底（拓扑排序 + 逐个更新）
  → syncFromTable() 读取卖价/规格/数量 → 更新 React state
  → 表单字段显示更新
```

### 5.3 状态流转流程

```
用户点击"下一节点"
  → POST /api/quotes/:id/next-status（需 quotes:status-transition 权限）
  → db.quotes.nextStatus() 切换状态 + 记录时间节点 + pendingAmount 联动
  → 返回更新后的 Quote → 前端刷新状态显示
```

### 5.4 订单对账流程（v28）

```
订单进入"已发货已收款"(5) → 出现在订单对账管理"待对账"列表
  → 对账页录入各环节工艺成本明细（quote_reconciliation_costs）
  → POST /api/quotes/:id/reconcile 确认对账
  → 状态 5→8，记录 reconciledTime，进入"已对账"列表
  → 需重新核对时 POST /api/quotes/:id/unreconcile（8→5，清空对账时间）
```

## 6. 关键技术决策

| 决策 | 原因 |
|---|---|
| VTable-Sheet 而非自研表格 | 内置公式引擎，支持 Excel 级联计算，减少开发量 |
| MySQL (mysql2/promise) | 成熟的关系型数据库，连接池管理，支持事务、生成列和触发器 |
| Zustand 而非 Redux | 轻量，仅认证状态需全局管理，页面状态用 useState |
| Tailwind CSS 而非 CSS Modules | 快速迭代，原子化样式便于布局调整 |
| 款式模板入库（v19/v23）+ 内置常量兜底 | 模板可在线可视化编辑，未选模板时内置默认仍可用 |
| recascadeDependents 兜底 | VTable 1.26.x 的 handleCellValueChanged 公式级联不可靠 |
| JWT 双 Token（access 内存 + refresh localStorage） | 降低 token 泄露风险，支持无感续期与 10 分钟闲置登出 |
| quote_history 触发器审计 | 数据库层自动捕获订单变更（含删除），不依赖应用层埋点 |
| 全表 COLLATE 统一 utf8mb4_unicode_ci（v26） | 避免 MySQL 8 默认 utf8mb4_0900_ai_ci 跨表 JOIN 报错 |

## 7. 部署架构

### 7.1 开发环境

```
npm run dev
  → concurrently 同时启动:
    → vite (前端 5173)
    → tsx watch api/index.ts (后端 3001)
  → Vite 代理 /api → localhost:3001
```

### 7.2 生产部署（PM2 + 远程脚本）

部署脚本 `scripts/deploy-remote.sh`（v2.0 本地构建模式）：

```
本地: npm run build（vite build → dist/ + tsc → api/dist/）
  → 1. Git 提交与推送
  → 2. 版本号递增 + Git 标签（vX.Y.Z）
  → 3. 本地构建（前端 + 后端）
  → 4. 打包上传远程服务器（源码 + 构建产物分开打包，服务器目录 /usr/X-prod）
  → 5. 远程安装生产依赖（npm install --omit=dev）
  → 6. 重启 PM2 服务（进程名 X-api，端口 3003）
  → 7. 健康检查（/api/health + 前端页面 + API 性能 + 缩略图验证）
  → 失败时自动回滚到上一版本（备份 tar 包恢复）
```

服务器：`/usr/X-prod`，PM2 进程 `X-api` 监听 3003 端口，后端同时托管前端静态资源（SPA 模式）。

### 7.3 环境配置

`api/.env`（或根目录 `.env`）：
```
PORT=3001                        # 后端端口（生产 3003 由服务器 .env 指定）
NODE_ENV=development|production
MYSQL_HOST=127.0.0.1             # MySQL 主机地址
MYSQL_PORT=3306                  # MySQL 端口
MYSQL_USER=root                  # MySQL 用户名
MYSQL_PASSWORD=                  # MySQL 密码
MYSQL_DATABASE=quote_system      # MySQL 数据库名称
JWT_SECRET=                      # access token 签名密钥
JWT_REFRESH_SECRET=              # refresh token 签名密钥
JWT_ACCESS_EXPIRES_IN=15m        # access token 有效期
JWT_REFRESH_EXPIRES_IN=7d        # refresh token 有效期
HOST=                            # 可选：显式绑定网卡地址
EXPORT_STORAGE_PATH=./exports    # Excel 导出存储路径
```
