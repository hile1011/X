# 数据库文档

> 版本：v1.2.x
> 日期：2026-09-10
> 数据库引擎：MySQL 8.0+（通过 mysql2/promise 连接池）
> Schema 版本：v28（CURRENT_SCHEMA_VERSION = 28）
> 全量脚本：db/schema/schema_v28.sql（与 api/migrations/index.ts 同步维护）

---

## 1. 概览

### 1.1 技术栈

| 项目 | 说明 |
|------|------|
| 数据库引擎 | MySQL 8.0+（utf8mb4 字符集，全表 COLLATE 统一 utf8mb4_unicode_ci） |
| 连接方式 | mysql2/promise 连接池 |
| 数据库配置 | 通过环境变量 `MYSQL_HOST`/`MYSQL_PORT`/`MYSQL_USER`/`MYSQL_PASSWORD`/`MYSQL_DATABASE` 配置 |
| 迁移机制 | `MigrationRunner` 类（api/migrations/index.ts），版本化管理 schema 变更，支持幂等 up/down |
| 全量脚本 | `db/schema/schema_v28.sql`（表结构 + 触发器 + 种子数据），空库初始化用 |
| 当前 Schema 版本 | v28 |

### 1.3 关联关系说明

> ⚠️ **注意**：本数据库未使用物理外键约束，关联关系通过应用层逻辑维护。

```
customers (1) ──逻辑──< (N) quotes              通过 customers.name = quotes.customerName
quotes   (1) ──逻辑──< (N) quote_production_tasks 通过 quote_production_tasks.quote_id = quotes.id
quotes   (1) ──逻辑──< (N) quote_reconciliation_costs 通过 quote_reconciliation_costs.quote_id = quotes.id
quotes   (1) ──逻辑──< (N) quote_history          通过 quote_history.quote_id = quotes.id
sheet_templates (1) ──逻辑──< (N) quotes         通过 quotes.template_id = sheet_templates.id
users (N) ──< user_roles >── (N) roles ──< role_permissions >── (N) permissions
```

**状态机**（`status`，v14 重构为指针模式，v28 新增对账）：

```
1 报价中 → 2 打样中 → 7 打样完成 → 3 做货中 → 4 已发货未收款 → 5 已发货已收款 → 8 已对账（终态）
                                                    └────────────────────────────┘ 仅经订单对账管理
1 / 2 / 7 ──── endQuote ────→ 6 结束（旁路状态）
```

- `nextStatus`：1→2→7→3→4→5 顺序推进，每步自动记录对应时间戳；5 不再前进（5→8 仅可经 `reconcileQuote` 确认对账进入）
- `prevStatus`：逆序回退（2→1, 7→2, 3→7, 4→3, 5→4, 6→5）；8 不可手动回退（8→5 仅可经 `unreconcileQuote` 退回对账）
- `endQuote`：从状态 1/2/7 直接跳到 6（结束）
- `reconcileQuote`（v28）：5→8，记录 reconciledTime
- `unreconcileQuote`（v28）：8→5，清空 reconciledTime（重新核对后可再次确认）

**订单号生成逻辑**：16 位随机数字，生成后查询 quotes 表防碰撞（重试 10 次），兜底时间戳(13位)+3位随机数；创建后不再随客户名称/款式变化。

## 3. 迁移机制

### 3.1 MigrationRunner

迁移定义位于 `api/migrations/index.ts`，核心常量 `CURRENT_SCHEMA_VERSION = 28`。

- **版本化**：`migrations` 数组按 version 递增排列（v1 → v28，禁止跳号/修改已发布迁移）
- **幂等 up**：DDL 用 `IF NOT EXISTS` / 列存在性检查（information_schema），DML 用 `INSERT IGNORE`，可安全重复执行
- **down 必须提供**：逆序撤销 up 的所有操作
- **执行记录**：`schema_migrations` 表记录已应用版本；启动时比对自动执行未应用的迁移
- **规范**：name 用 kebab-case，description 以版本标签开头（如 `V0.20：`）；大表数据迁移分批处理（每批 ≤ 1000 行）

### 3.2 全量脚本 schema_vN.sql

位于 `db/schema/schema_v28.sql`，每次新增迁移后同步维护：

- 包含全部表结构（`CREATE TABLE IF NOT EXISTS`）+ 触发器（`DROP TRIGGER IF EXISTS` + `CREATE TRIGGER`）+ 种子数据（`INSERT IGNORE`）+ schema_migrations 记录（标记 v1-v28 全部已执行）
- 可安全重复执行；用于新环境初始化（替代逐个执行增量迁移）与测试环境快速重建
- 执行方式：`mysql -u root -p <database_name> < db/schema/schema_v28.sql`

### 3.3 COLLATE 统一（v26）

所有表统一 `COLLATE utf8mb4_unicode_ci`。v23/v24 增量建表时未显式指定 COLLATE，落到 MySQL 8 默认 `utf8mb4_0900_ai_ci`，与 quotes 等表 JOIN 时报 `Illegal mix of collations`（做货跟踪总览接口 500），v26 迁移统一修复，此后新增表（如 v28）均显式指定。

## 4. 触发器与审计（v13）

`quotes` 表三个触发器自动写入 `quote_history`：

| 触发器 | 时机 | 记录内容 |
|--------|------|---------|
| `quotes_audit_insert` | AFTER INSERT | action=insert，new_values 快照 |
| `quotes_audit_update` | AFTER UPDATE | action=update，old/new 快照 + changed_fields 变更字段列表 |
| `quotes_audit_delete` | AFTER DELETE | action=delete，old_values 快照 |

- 单语句触发体（无 BEGIN...END），可被 mysql 客户端直接执行
- `operator` 优先取应用层 `@app_operator` 会话变量（应用启动时按操作人设置），回退 `CURRENT_USER()`
- 追踪 36 个业务字段（排除 id/created_at/updated_at、created_by/updated_by 操作人字段及 6 个 LONGTEXT 大字段）
- v17 新增的收款字段（actualSampleFee/sampleFeeDeduct/deposit/pendingAmount）纳入变更追踪

## 6. 数据库操作层

### 6.1 架构

```
api/dbClient.ts
  ├── pool                    # mysql2 连接池单例
  ├── initDatabase()          # 确保 MySQL 数据库存在
  ├── withTransaction(fn)     # 事务封装（独占连接）
  ├── execMultiStatement(sql) # 多语句拆分执行（用于迁移 DDL）
  └── closePool()             # 关闭连接池

api/db.ts
  ├── createWrapper()         # 包装 mysql2，提供 exec/prepare/transaction/close
  ├── MigrationRunner         # 迁移管理
  └── dbApi                   # 业务 CRUD 操作
      ├── customers / products / orders / tasks / processCosts
      ├── quotes              # CRUD + 状态流转 + 复制
      ├── productionTasks     # 做货流程任务
      ├── reconciliation      # 对账成本明细 + reconcileQuote/unreconcileQuote（v28）
      ├── sheetTemplates      # 款式模板（一对多）
      ├── users / roles / permissions（RBAC）
      └── operationLogs       # 操作日志
```

### 6.2 关键实现细节

| 机制 | 说明 |
|------|------|
| `sanitize()` | `run/get/all` 方法将 `undefined` 参数转为 `null`，防止 mysql2 绑定报错 |
| `withTransaction()` | 获取独占连接 → BEGIN → 执行 fn → COMMIT/ROLLBACK → 释放连接（对账明细整体替换即事务：删 + 批量插） |
| `execMultiStatement()` | 按分号拆分 SQL 逐条执行（mysql2 默认 multipleStatements=false，防 SQL 注入） |
| `toCamelRow()` | 字段名透传（数据库字段名与 TS 接口字段名一致，无需转换） |
| `generateUniqueQuoteNumber()` | 16 位随机数字订单号，防碰撞重试 10 次，兜底时间戳+随机数（导出供单测覆盖） |
| JSON 字段序列化 | images / tableData / formulas / materials 等存 JSON 字符串（LONGTEXT），读取时 `JSON.parse`，写入时 `JSON.stringify` |

### 6.3 时间字段处理

| 字段类别 | 存储格式 | 示例 |
|----------|----------|------|
| `created_at` / `updated_at` | MySQL `DATETIME DEFAULT CURRENT_TIMESTAMP` | `2026-09-10 14:30:00` |
| `quoteTime` 等业务时间 | `VARCHAR(64)`，`toISOString().split('T')[0]` | `2026-09-10` |

### 7.2 保存逻辑（handleSave）

```
1. 同步客户：customerName.trim() 非空时
   → getByName(customerName) → 存在则 update(address)，不存在则 create(name, address)
2. 构造 quoteData = { ...orderInfo, 四个价格字段, 收款字段, status, images, 表格快照字段 }
3. 新建模式 → api.quotes.create(quoteData)（后端生成 16 位随机订单号 + 初始化状态 1）
   编辑模式 → api.quotes.update(id, quoteData)（订单号保持不变）
4. 请求附带 Authorization + X-Operator 审计头；401 时自动刷新 token 重试
```

### 7.3 页面逻辑一致性

| 检查项 | 数据库 | 前端 | 状态 |
|--------|--------|------|------|
| customers.name / quotes.customerName 必填 | NOT NULL | handleSave 中 trim() 检查 | ✅ 一致 |
| quotes.productStyle 默认值 | DEFAULT '1' | 加载时 `\|\| '1'` | ✅ 一致 |
| fabricMaterial / process / handleMaterial 默认值 | 建表默认值 | 加载时空值回填默认值 | ✅ 一致 |
| images JSON 序列化 | LONGTEXT | 读取 JSON.parse，写入 JSON.stringify | ✅ 一致 |
| 款式模板加载 | template_id + sheet_templates | 数据库模板优先，内置常量兜底 | ✅ 一致 |
| 状态 5→8 流转 | 仅 reconcileQuote | 订单对账管理页面触发 | ✅ 一致 |
