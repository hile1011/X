# 数据库文档

> 版本：V0.2
> 日期：2026-07-31
> 数据库引擎：sql.js（WASM 版 SQLite），本地文件持久化（`./data/quote-system.db`）
> Schema 版本：v2（V0.2 新增 costPrice 字段）

---

## 1. 概览

### 1.1 技术栈

| 项目 | 说明 |
|------|------|
| 数据库引擎 | sql.js（基于 WASM 的 SQLite 实现） |
| 持久化方式 | 内存数据库 + 文件写入（`fs.writeFileSync`） |
| 数据库文件 | `./data/quote-system.db`（可通过 `DB_PATH` 环境变量配置） |
| 迁移机制 | `MigrationRunner` 类，版本化管理 schema 变更 |
| 当前 Schema 版本 | v2（`initial-schema` + `add-cost-price`） |

### 1.2 表清单

| 表名 | 用途 | 关联 |
|------|------|------|
| `schema_migrations` | 迁移版本记录 | — |
| `customers` | 客户信息 | 被 `quotes.customerName` 逻辑关联（非外键） |
| `products` | 产品信息 | 被 `order_items.product_id` 引用 |
| `orders` | 订单 | `customer_id` → `customers.id`（逻辑关联） |
| `order_items` | 订单明细 | `order_id` → `orders.id` |
| `tasks` | 跟单任务 | `order_id` → `orders.id`（逻辑关联） |
| `quotes` | 报价单（核心业务表） | `customerName` → `customers.name`（逻辑关联） |
| `process_costs` | 工艺成本 | — |

### 1.3 关联关系说明

> ⚠️ **注意**：除 `order_items.order_id` 外，本数据库未使用物理外键约束。关联关系通过应用层逻辑维护。

```
customers (1) ──逻辑──< (N) quotes     通过 customers.name = quotes.customerName
customers (1) ──逻辑──< (N) orders     通过 orders.customer_id = customers.id
orders    (1) ──逻辑──< (N) order_items 通过 order_items.order_id = orders.id
orders    (1) ──逻辑──< (N) tasks       通过 tasks.order_id = orders.id
products  (1) ──逻辑──< (N) order_items 通过 order_items.product_id = products.id
```

**索引**：
- `idx_quotes_customerName` — quotes.customerName
- `idx_quotes_status` — quotes.status
- `idx_orders_customer_id` — orders.customer_id
- `idx_orders_status` — orders.status
- `idx_tasks_status` — tasks.status

**状态机**（`status`）：

```
1 报价中 → 2 打样中 → 3 做货中 → 4 已发货未收款 → 5 已发货已收款 → 6 结束
```

- `nextStatus`：顺序推进，每步自动记录对应时间戳
- `prevStatus`：逆序回退（不清除时间戳）
- `endQuote`：从状态 1 或 2 直接跳到 6（结束）

**页面逻辑一致性**：
- `customerName` 是唯一必填字段（前端 `handleSave` 中 `customerName.trim()` 非空才保存）
- 数据库 `quote_number` 为 NOT NULL，由后端自动生成
- `sampleFee` 和 `sampleDays` 在前端合并为一个文本输入框"打样费/天"，格式 `费用/天数`，保存时拆分为两个字段
- `handleMaterial` 和 `handleSpec` 在前端合并为一个文本输入框"手提"，格式 `材质：规格`
- `fabricMaterial`、`process`、`handleMaterial` 有默认值，加载时若为空则填充默认值
- `productionTimeStart` 默认为当天，`productionTimeEnd` 通过 `massDays` 联动计算
- `sellPriceNoTax`、`sellPriceWithTax` 由在线表格(VTable)公式计算，非用户直接输入
- `images` 在数据库中存储为 JSON 字符串，读取时自动解析为数组
- 前端加载时 `sampleFee` 会清理尾部"元"字符：`(data.sampleFee || '').replace(/元$/, '')`

## 3. 数据库操作层（db.ts）

### 3.1 架构

```
api/db.ts
  ├── initSqlJs()              # 初始化 sql.js WASM
  ├── createWrapper(db)        # 包装 sql.js，提供 prepare/run/get/all/transaction
  ├── persist()                # 内存数据库 → 文件持久化
  ├── MigrationRunner          # 迁移管理
  └── dbApi                    # 业务 CRUD 操作
      ├── customers
      ├── products
      ├── orders
      ├── tasks
      ├── quotes
      └── processCosts
```

### 3.2 关键实现细节

| 机制 | 说明 |
|------|------|
| `sanitize()` | `run/get/all` 方法将 `undefined` 参数转为 `null`，防止 sql.js 绑定报错 |
| `persist()` | 每次 CUD 操作后调用 `rawDb.export()` + `fs.writeFileSync` 写入文件 |
| `toCamelRow()` | 字段名透传（数据库字段名与 TS 接口字段名一致，无需转换） |
| `images` 序列化 | `quotes` 表中 `images` 存为 JSON 字符串，读取时 `JSON.parse`，写入时 `JSON.stringify` |
| `quote_number` 生成 | 创建时：`{customerName}-{yyyyMMddHHmmss}-{款式标签}`；更新时：保留原时间戳，替换客户名和款式 |

### 3.3 时间字段处理

| 字段类别 | 存储格式 | 示例 |
|----------|----------|------|
| `created_at` / `updated_at` | `datetime('now','localtime')` | `2026-08-03 14:30:00` |
| `quoteTime` 等业务时间 | `toISOString().split('T')[0]` | `2026-08-03` |
| `updated_at`（代码写入） | `new Date().toISOString()` | `2026-08-03T06:30:00.000Z` |

> ⚠️ 注意：`created_at` 使用 SQLite 的 `datetime('now','localtime')` 生成（本地时间），而代码中 `updated_at` 使用 `new Date().toISOString()`（UTC 时间），两者格式不一致。

| customerName | customerName | string | 文本输入（CustomerSelect 组件） |
| shippingAddress | shippingAddress | string | 文本域 |
| productStyle | productStyle | string | 下拉选择 |
| productSpec | productSpec | string | 文本输入 |
| fabricMaterial | fabricMaterial | string | 文本输入 |
| process | process | string | 文本输入 |

| handleSpec | handleSpec | string | 合并输入"手提"（后半部分） |
| quantity | quantity | string | 文本输入 |
| boxSpec | boxSpec | string | 文本输入 |
| remark | remark | string | 文本域 |
| sampleFee | sampleFee | string | 合并输入"打样费/天"（前半部分） |
| sampleDays | sampleDays | string | 合并输入"打样费/天"（后半部分） |
| massDays | massDays | string | 文本输入 |

> **注意**：前端所有业务字段均为 `string` 类型，包括数量(quantity)和天数(days)，数据库中也对应 `TEXT` 类型。卖价(`sellPriceNoTax`/`sellPriceWithTax`)和状态(`status`)不包含在 `OrderInfo` 中，在 `handleSave` 时单独附加。

### 4.2 合并字段说明

前端将多个数据库字段合并为单个输入框显示：

| 前端输入框 | 合并的数据库字段 | 分隔符 | 示例 |
|------------|-----------------|--------|------|
| 打样费/天 | sampleFee + sampleDays | `/` | `100/3` |
| 手提 | handleMaterial + handleSpec | `：`（全角冒号） | `帆布手提：2.5*70` |

### 4.3 保存逻辑（handleSave）

```
1. 同步客户：customerName.trim() 非空时
   → getByName(customerName)
   → 存在则 update(address)，不存在则 create(name, address)
2. 构造 quoteData = { ...orderInfo, sellPriceNoTax, sellPriceWithTax, status, images }
3. 新建模式 → api.quotes.create(quoteData) → 跳转 /quotes
   编辑模式 → api.quotes.update(id, quoteData) → 留在当前页
4. 错误处理 → setSaveError(message) → 5秒后清除
```

### 5.2 ⚠️ 潜在问题

| 检查项 | 问题 | 影响 | 建议 |
|--------|------|------|------|
| 时间格式不一致 | `created_at` 用 localtime，`updated_at` 用 ISO(UTC) | 时间显示可能混乱 | 统一使用一种格式 |
| quotes.customerName 唯一性 | 无 UNIQUE 约束 | 可能出现重名客户 | 应用层 `getByName` 返回首条，风险可控 |
| orders/order_items 表闲置 | 业务流程走 quotes 表 | 表结构冗余 | 如无后续计划可考虑移除 |
| tasks.title 前端无验证 | 数据库 NOT NULL 兜底 | 空标题提交会 500 | 前端添加 required |
| quotes.user_id/customer_id 闲置 | 始终为空字符串 | 关联关系未实际使用 | 如不需要可移除 |
| sampleFee 旧数据"元"后缀 | 历史数据可能含"元" | 加载时已清理 | 已修复 |
